Documentation

Everything needed to install, understand, operate and extend the Danube Bank banking system.

Demo software. No real money, card network connectivity or KYC provider is involved. Card numbers are generated locally and accounts are seeded with fictitious balances.

Overview

Danube Bank is a two-application system sharing one MySQL database:

  • Customer app (app/, port 8000) — online banking for customers.
  • Operator app (admin_app/, port 8001, “Danube Ops”) — bank management, including live database tools.

Both import the same ORM models and the same banking service layer, so there is exactly one implementation of money movement. The operator app uses the same ledger functions rather than editing balances directly.

Quick start

Requirements: Docker Desktop and Python 3.11+.

docker compose up -d
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
cp .env.example .env
python -m scripts.seed
uvicorn app.main:app --reload
uvicorn admin_app.main:app --port 8001

Open http://127.0.0.1:8000 for customers and http://127.0.0.1:8001 for operators.

Runtime settings (MySQL)

Institution name, support email, currency, transfer and cash limits, overdraft, savings interest, card limits, loan rates and limits, maintenance mode and demo-login visibility all live in the settings table. Operators edit them in Settings; both apps refresh their cache every 10 seconds. Changes are audited individually.

Ledger design

Money is stored in integer cents. A transaction is a header row; each account touched gets a ledger_entries row with the signed amount and the resulting balance.

Transaction  TXN-8F2A…   transfer   250.00 USD
 ├─ LedgerEntry  account A   −25000   balance_after 175000
 └─ LedgerEntry  account B   +25000   balance_after  25000
  • post_transaction() locks every involved account with SELECT … FOR UPDATE, ordered by id to avoid deadlocks.
  • It validates account status, currency, and available funds (balance + overdraft) before writing.
  • Multi-entry transactions must sum to zero. Single-sided entries represent the bank's external position for deposits, withdrawals, interest and card payments.
  • Idempotency keys are supported and unique, so retried requests cannot double-charge.
  • Reversal posts the mirror entries and marks the original reversed; nothing is deleted.

Security model

  • Passwords and card PINs use scrypt with per-secret salts; comparisons are constant-time.
  • Card PANs are Fernet-encrypted; lists only ever show the last four digits. Reveal is a separate audited request and can be disabled in Settings.
  • Every mutating form carries a CSRF token bound to the session.
  • Customers can only read or move money on accounts they own; ownership is checked server-side on every route.
  • The operator app has its own cookie name and signing key, and refuses non-admin accounts.
  • All operator actions are appended to audit_logs with actor, IP and detail.
This is a demo. There is no TLS termination, MFA, distributed rate limiting, email verification or real KYC integration. Do not use it to handle real money.

Accounts, transfers and statements

Customers can hold up to the configured number of open accounts. Checking accounts carry an overdraft facility; savings accounts accrue interest through the daily batch job.

Transfers are local (same bank, same currency). The recipient account is resolved by account number, validated, and both accounts post in one database transaction. Receipts are addressable by reference, CSV exports and printable statements are generated from ledger entries.

Standing orders support daily, weekly and monthly frequencies. When the batch job runs, due plans execute; if funds are insufficient the plan is paused and the customer is notified.

Cards

Cards use the demo BIN 400000 and a Luhn check digit. Issuing generates a 4-digit PIN unless one is supplied. Daily limits are enforced per card and reset automatically on the next day. Operators can freeze, cancel, change limits and reset PINs from either app.

Loans

Loan pricing is a base rate with discounts for verified KYC and larger amounts, all configurable in Settings. Approval creates an annuity amortisation schedule, disburses principal to the chosen account and marks instalments paid as they are repaid. Early repayment closes the loan immediately.

Operator app (Danube Ops)

Sign in at http://127.0.0.1:8001 with an account whose role is admin.

  • Customers — create, edit, lock/unlock, change role, reset password, set KYC.
  • Accounts — open accounts, freeze/activate/close, post audited credit or debit adjustments.
  • Transactions — search the ledger, inspect entries per account, reverse a completed transaction with a reason.
  • Cards — issue, reveal, freeze, cancel, set limits, reset PIN.
  • Loans — approve, reject, or book and disburse a loan on behalf of a customer.
  • Settings — edit every runtime business rule.
  • Audit — search every operator and system event.

Database tools

The operator app includes a real database explorer:

  • Browse any table with sorting and pagination.
  • Export any table to CSV.
  • Backup streams a full SQL dump (CREATE TABLE + INSERT) with foreign-key checks disabled.
  • SQL console — SELECT always allowed; INSERT/UPDATE/DELETE only when ALLOW_ADMIN_SQL_WRITE=1; DROP/TRUNCATE/ALTER/CREATE/GRANT always blocked. Every statement is audited.

Testing

pytest

Unit tests cover Luhn generation, scrypt hashing, annuity maths and money formatting. Ledger tests run against MySQL, verify balanced entries, overdraft limits, ownership checks and idempotency, then roll back so they leave no data behind. If MySQL is not reachable they skip.

Deployment

For a shared environment:

  • Set a strong SECRET_KEY and change every database password.
  • Run behind a TLS-terminating reverse proxy (Caddy, nginx, Cloudflare Tunnel).
  • Set https_only=True on both session middlewares.
  • Disable the demo login shortcuts and card reveal in Settings.
  • Schedule POST /admin/run-jobs (customer app) or use the operator app to run daily accruals.
  • Keep MySQL on a private network and back it up using the operator backup endpoint or mysqldump.
